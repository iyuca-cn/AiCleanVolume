# 扫描进度性能优化设计

## 背景

扫描页在扫描期间以 20ms 间隔刷新进度状态。每次刷新都会写入状态标签、用时标签、`AntdUI.Progress.Value`、`State` 和 `Loading`。其中 `Progress.Value` 会触发控件动画与重绘，`Loading=true` 还会启动 AntdUI 内部加载动画。两层高频动画叠加后，扫描期间 UI 渲染压力明显增大。

## 目标

- 保留扫描期间进度条连贯动画。
- 降低重复控件写入和重绘频率。
- 不修改扫描 provider、CLI、目录树数据结构和微内核边界。

## 方案

扫描进度仍由 WinForms `Timer` 驱动，但把刷新职责拆开：

- 进度值以约 100ms 间隔更新，AntdUI 补间动画固定为 60ms，保证每个刷新周期内都追上当前进度，不让视觉进度拖慢。
- 用时文本以约 100ms 间隔更新，满足 0.1 秒粒度的实时用时显示。
- 状态文本、进度状态和 `Loading` 只在开始、完成、失败等状态切换时写入。
- 扫描中的 `Progress.Loading` 不再保持开启，避免 AntdUI 内部 loading 循环与外部进度补间叠加；连续动效由短时 `Progress.Value` 补间承担。
- 完成和失败状态仍立即刷新，不受节流影响。

## 验证

- Debug 编译通过。
- 扫描开始时进度条从非零值平滑推进。
- 扫描完成时进度条立即到 100%，用时显示真实耗时。
- 扫描失败时进度条进入错误态。
