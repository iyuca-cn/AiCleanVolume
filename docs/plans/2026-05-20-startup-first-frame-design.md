# 启动首帧与任务栏响应设计

## 背景

主窗口启动时会一次性创建大量 AntdUI 控件，并在构造阶段同步加载设置、AI 配置卡片和磁盘摘要。任务栏按钮要等窗体显示和消息循环进入后才出现，因此构造阶段越重，用户越晚看到任务栏图标。

## 目标

启动时尽快创建可见窗体和任务栏按钮，同时避免未完成布局的控件逐步绘制。首屏先显示稳定占位数据，设置、磁盘列表和摘要在首帧后补齐。

## 方案

- 保留现有 AntdUI 主窗口和微内核服务组织方式。
- 构造阶段只创建控件树、表格列和首屏占位值，不同步加载设置、AI 配置卡片、磁盘列表或磁盘容量。
- 继续使用现有 `WM_SETREDRAW` 暂停首轮控件重绘，避免控件构建时多次刷新。
- `OnLoad` 只处理侧边栏宽度和窗口边界，让窗体尽快进入显示流程。
- `OnShown` 后排队执行首轮布局/重绘恢复，再排队执行设置和磁盘数据绑定。
- 启动数据绑定期间用 `loadingStartupUi` 屏蔽联动事件，绑定完成后统一刷新磁盘摘要和提示词。
- 不使用窗体 `Opacity` 或 layered window 隐藏启动帧，避免影响最小化恢复后的 DWM 绘制路径。
- 对 `WM_ERASEBKGND` 使用应用页面背景色擦除，避免恢复期系统擦背景时露出黑色客户端。

## 数据流

构造阶段设置默认盘符占位和空摘要。句柄创建后暂停主窗口重绘。`OnLoad` 完成侧边栏宽度和窗口边界修正。`OnShown` 先恢复首轮布局和重绘，再通过 UI 队列执行 `LoadSettingsToUi()` 与 `LoadDrives()`，最后统一刷新磁盘摘要、提示词和启动日志。

## 错误处理

如果窗口已释放、句柄未创建或启动恢复流程已执行，则不重复处理。启动绑定期间事件处理器直接返回，避免占位赋值和真实绑定触发重复磁盘摘要、提示词和配置预设计算。该方案不引入回退路径，不修改第三方 AntdUI 源码，并保留最小化恢复的强制重绘流程。

## 验证

执行 Debug 编译，确认 `MainWindow` 可编译。手动启动桌面程序，观察任务栏按钮是否更快出现且首屏稳定。自动化截图采样检查启动后不是黑屏，并检查最小化后恢复仍能正常重绘。
